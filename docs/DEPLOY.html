聰動運動：上傳到 GitHub Pages

網站的 index.html 與 JS、CSS、models、vendor、assets 在專案根目錄，不再放在 SmartAction_Basketball_20261007/。本工具固定對應 kuonanhong/3x3Basketball，以 SSH 金鑰驗證，不使用 PAT。

1. 確認本機工具

git --version
python3.11 --version
ssh -T git@github.com

看到 Hi kuonanhong! You've successfully authenticated 即成功；GitHub 不提供互動式 shell，所以此測試回傳 1 不代表認證失敗。若出現 Permission denied (publickey)，請確認 GitHub → Settings → SSH and GPG keys 已加入這台電腦的公開金鑰，以及 SSH agent 能使用對應私鑰。不要公開私鑰或把 PAT 寫入專案。

腳本使用 macOS 內建 Bash 3.2 可支援的語法，並內嵌 Python 3.10 以上的標準函式庫程式；沒有額外 pip 相依套件。優先使用 python3.11，再嘗試 python3；可用 SPORTS_PYTHON=/完整路徑/python3 指定 Python。

2. 解壓縮後，切換到專案目錄

找出同時包含 index.html、deploy-manifest.json 與 Upload_SmartAction_Sports.sh 的資料夾。在終端機輸入 cd （後面留一個空白），把該資料夾拖入終端機，再按 Enter。路徑含中文與空白可正常使用。

bash Upload_SmartAction_Sports.sh --dry-run

這一步讀取 GitHub main、驗證檔案大小與 SHA-256，列出新增、修改、刪除、保留的完整計畫。它會建立本機獨立 Git 快取，但不推送任何遠端分支，也不改動您的本機專案。

3. 正式上傳

bash Upload_SmartAction_Sports.sh --push

若尚未設定 Git 作者姓名/email，可先設定自己的資料，或用下列參數：

bash Upload_SmartAction_Sports.sh --push \
  --name "您的姓名" --email "您的 GitHub 提交 email"

上傳順序是：建立舊 main 的完整備份分支 → 分批推送暫存分支 → 驗證完整檔案樹 → 確認 main 期間未被他人更新 → fast-forward 更新 main。備份分支名稱為 sports-backup/原始完整SHA，暫存分支為 sports-upload/...。不使用 force push。

預設每批目標 64 MiB，不會將單一檔案硬拆分；網站模型已事先分為每片 32 MiB。網路中斷時，重跑同一指令，可略過遠端已確認收到的批次。失敗的當前批次仍可能需要重新傳輸，這不是單一檔案內的逐位元續傳。

# 只上傳暫存分支，可稍後發布
bash Upload_SmartAction_Sports.sh --push --stage-only

# 繼續並發布
bash Upload_SmartAction_Sports.sh --push

5. 修改後如何再次更新？

新增圖片、程式或模型檔後，請先使用套件提供的建置清單工具重新產生部署清單：

python3 tools/build_manifest.py
bash Upload_SmartAction_Sports.sh --dry-run
bash Upload_SmartAction_Sports.sh --push

如果只修改既有清單檔案、沒有增加或刪除檔案，可使用：

bash Upload_SmartAction_Sports.sh --refresh-manifest
bash Upload_SmartAction_Sports.sh --dry-run
bash Upload_SmartAction_Sports.sh --push

模型分塊除了外層部署清單，還有 .parts.json 的分塊 SHA、大小、總 SHA 驗證。修改模型不能只更新外層清單，必須同時重建正確的分塊清單，並保持模型格式與瀏覽器推論程式相容。

6. 開啟 Pages

GitHub 儲存庫 → Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save。等待 Actions 顯示部署成功，再開啟 https://kuonanhong.github.io/3x3Basketball/。如果您原先使用自訂 Actions 工作流程，需確認該工作流程發布的是根目錄內容。

GitHub Pages 是靜態主機；它不會執行 Python，也不提供伺服器端推論。本套件的模型由使用者瀏覽器下載並在自己的裝置上運算。首次模型下載約半 GB，行動網路及裝置記憶體成本由使用者承擔。免費託管不表示無限流量、十萬人同時下載可保證不受限。

腳本以單檔小於 100 MiB、整個保留後網站小於 1,000,000,000 bytes 作為保守發布檢查。模型過大時應改用外部模型託管或較小模型；單純將檔案分塊並不能繞過網站總容量限制。

7. 常見狀況

  • 找不到專案：加入 --source "/完整專案路徑"，路徑要加引號。
  • SHA 不符：確認本機修改後再重新建置清單；若是下載損毀，重新解壓縮完整附件。
  • 上傳中斷：原指令重跑。Git 已接收的批次會被檢查後接續。
  • main 被其他人更新：重跑，依新的 main 再比較，不強制覆蓋。
  • 快取鎖定：先確認另一個上傳程序已結束；再依錯誤提示刪除指定 running.lock 目錄後重跑，不要在上傳仍執行時移除鎖定。
  • 頁面仍舊：先看 GitHub Actions 是否成功，再重新整理。模型載入與頁面部署完成是不同檢查。
